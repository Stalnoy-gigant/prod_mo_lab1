## Блок 1: Конструктивное число

**Идея:** тип данных для представления вещественного числа в виде пары рациональных чисел `[a, b]` с шириной интервала `ε = b - a`.

**Создание:**
- `ConstructiveNumber.from_real(x, eps)` — из вещественного числа и точности
- `ConstructiveNumber.from_pair(a, b)` — из пары рациональных

**Арифметика** реализована через интервальную арифметику:
- `+`, `-`, `*`, `/` — через операции над границами интервала
- Деление: берётся обратный интервал, потом умножение
- `**n` — через повторное умножение

**Получение значения:** `cn.get(alpha)`, где `alpha ∈ [0, 1]`:
- `alpha=0` → левая граница `a`
- `alpha=1` → правая граница `b`
- `alpha=0.5` → середина интервала

**Наблюдение:** при каждой арифметической операции ε растёт — это неизбежное следствие интервальной арифметики (см. график `eps_growth_arithmetic.png`).

Реализация: [src/constructive_number.py](./src/constructive_number.py)

## Блок 3: Методы оптимизации

### 0-й порядок — Nelder-Mead (деформируемый многогранник)

Не использует производные. Симплекс из `n+1` вершин деформируется: отражение, растяжение, сжатие, уменьшение.

### 1-й порядок — Градиентный спуск

`x_{k+1} = x_k - lr * ∇f(x_k)`

Используется backtracking line search (Armijo) для автоматического подбора шага.

### 2-й порядок — Метод Ньютона

`x_{k+1} = x_k - H⁻¹(x_k) * ∇f(x_k)`

Используется решение `H * d = ∇f`, затем backtracking для damped Newton.

Реализация: [src/optimizers.py](./src/optimizers.py)

### Влияние ε (конструктивное число)

Проверены три порядка: `ε ∈ {1e-2, 1e-4, 1e-6}`.

**Наблюдения:**
- При большом `ε = 1e-2` точность оптимизации ограничена снизу — метод не может сойтись точнее самого интервала.
- Метод Ньютона чувствителен к ε, так как использует арифметику CN для вычисления градиента: ε накапливается при вычислении степеней.
- Nelder-Mead наиболее устойчив к ε, т.к. напрямую сравнивает значения `float(f(x))`.
- С уменьшением ε результаты CN-версии приближаются к float-версии.

Графики: `eps_convergence.png`

## Выводы

1. **Метод Ньютона** сходится быстрее всего (квадратичная сходимость), но требует Гессиана и чувствителен к начальной точке на невыпуклых функциях.
2. **Градиентный спуск** c line search надёжен, но медленен на плохо обусловленных функциях (κ=100 — на порядки больше итераций).
3. **Nelder-Mead** работает без производных, но требует больше всего вызовов функции.
4. **Конструктивное число** корректно работает с оптимизаторами, но накапливает ε при каждой операции — особенно заметно при степенных вычислениях. Для точной оптимизации нужен малый начальный ε.
